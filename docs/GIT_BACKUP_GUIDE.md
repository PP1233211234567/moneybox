## 后续每阶段的备份

1. 修改前确认工作目录、分支和未提交改动；保存编辑器中的修改。
2. 完成一个可验证阶段后运行对应验证，检查 `git diff` 和待提交文件，不纳入密钥或个人数据。
3. 创建有具体说明的提交，例如“修复竖屏布局与金豆碰撞”；推送该提交到已核对的个人远程仓库。
4. 本地 commit 提供可回退记录，远程 push 提供另一份副本。只上传一次不能自动备份以后没有提交或推送的修改。

以下命令均在普通 PowerShell 的项目根目录执行；后两条需要先完成首次提交和远程配置。推送发生前应检查差异。

```powershell
Set-Location -LiteralPath 'D:\GameProjects\moneybox'
& 'D:\Apps\Git\cmd\git.exe' status --short --branch
& 'D:\Apps\Git\cmd\git.exe' diff
& 'D:\Apps\Git\cmd\git.exe' log --oneline -n 10
```

## 改错后的恢复方式

如果不确定要恢复哪一版，先保留当前修改，并查看旧版本；不要直接清空工作目录。可以请协作助手把目标 commit 放在独立目录运行比较，确认后再恢复需要的文件。

已经提交的单次错误，可以在保存现有改动、工作区干净后用 `git revert <错误提交的完整哈希>` 创建一条撤销提交，再验证并推送。此操作保留完整历史，发生冲突时先解决冲突。不建议使用强制推送或清空未提交改动来恢复。

还没有提交的修改不会出现在版本历史中；测试通过的每个阶段都应及时提交和推送。
