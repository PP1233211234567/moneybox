## D-017：收费与税务底稿不猜规则

- 状态：独立数据服务已验证，账本和 UI 待接入
- 决定：收费服务只按显式版本规则与生效范围估算；无匹配规则返回需人工填写，实际账单覆盖时保留估算差额和来源。税务服务按年度、居民配置、来源/类别、成本、境外已缴税、锁定汇率和凭证整理底稿；无核验有效规则包时固定返回 `NO_VALID_RULES`，不计算税额或抵免。
- 原因：不能把测试费率或未核验法律条款伪装为当前券商收费与正式税务结论。

## D-018：个人账本导入或交易后的待重估状态

- 状态：CSV 与自然语言确认的本地持久化路径已实现，正式行情重估仍待贯通
- 决定：CSV 全批确认或交易草稿确认后，将新 `ledger` 与 `valuation_pending={reason, ledger_hash}` 在同一 ProjectStore generation 保存；报价估值批次保存时也写入待映射标记，直到黄金映射/库存成功保存才清除。`PersonalFlow` 与个人页面遇到待重估标记时，把罐内金豆明确标为“上次完整快照”，不展示旧金额为当前总资产，暂停现金快捷映射。标记的账本 hash 采用 JSON 往返规范化计算，并在加载/保存时校验。
- 原因：账本变更、完整估值和黄金映射必须分阶段确认；任何一个中间阶段都不能让旧金额、旧金豆被误读为同版的当前资产。

## D-019：只读展示快照契约

- 状态：本地数据链路已实现，Android 壁纸与 iOS 小组件尚未接入
- 决定：`DisplaySnapshotService` 从一次已读出的项目 generation 生成版本化只读载荷，只包含数据种类、展示设置、映射与库存版本、所选罐的豆 ID/面额。当前账本 hash 与映射绑定、且没有待重估标记时才给出 `CURRENT`；其他已有完整库存的状态标为 `PREVIOUS_COMPLETE`，不发布旧金额。隐私模式与空罐载荷均不包含金额和币种，演示载荷必须带演示标记。App 与将来的壁纸复用同一契约。
- 原因：预览与正式壁纸可能同时读取数据，需要明确区分完整旧版与当前版，并把无关的账户、持仓、交易原文和税务数据挡在渲染边界外。载荷契约本身尚不能证明跨进程原子读取或壁纸 T27/T32 通过。

## D-022：结构化资产录入与手工完整重估

- 状态：本地数据、独立表单、手工报价编排和个人页导航已验证，生产行情和完整手机导航待做
- 决定：多账户、股票/ETF/基金身份、期初现金/持仓和同币种转账先产生带 generation、项目和命令指纹的预览；用户单独确认后，一次保存新账本与 `valuation_pending`。未完成首个个人现金开户时禁用该路径，避免生成有账本无展示版本的死端项目。手工重估从当前账本推导全部持仓、全部账户现金、去重汇率和黄金需求；每项价格、单位、报价时间、来源说明由用户输入，精确覆盖、十进制和时效校验后预览。确认后先保存完整估值，再应用黄金映射和库存；第二步失败明确返回已保存估值、保留待重估标记，不发布旧金额为当前。

- 决定：流水页从已保存的个人账本读取事件，按入账序号倒序显示，单独标注生效时间。账户和本地文字搜索只过滤展示；冲销的原事件仍列出并标“已冲销”。点击后只展示已保存的白名单字段，不将成交价推断成当前行情或市值；隐私模式隐藏流水内容并禁用搜索。页面任何操作都不写账本。正式更正须走另一条确认命令。
- 限制：目前最多显示最近 100 条匹配流水，尚无分页、凭证、导出、手机无障碍与完整更正界面。

## D-028：对账页只比较可证明的账本事实

- 状态：本地只读服务、Godot 页面及测试通过；完整对账尚未实现
- 决定：对账页固定当前账本 hash 与账单截至 UTC 时间，逐账户输入同一时间的账单现金、有效持仓数量、已记录买卖手续费，并明确声明待交收情况。缺项、未映射或未声明时返回“资料不足”；明确无待交收时才在已有范围内列示差异。券商账户总额只保留为“未验证检查点”，差额绝不自动变成现金、收益或成本；整个页面不调用账本写入。
- 限制：当前 LedgerCore 缺待交收建模，完整账户总额需要同时间的锁定估值；券商适配与真机表单未做，结果总带 `full_reconciliation=false`。

## D-029：历史估值与收益只在完整边界上计算

- 状态：独立输入契约和本地数值测试通过，未接正式历史持久化
- 决定：历史区间只使用实际记录的完整估值点，不插造日线。调用方需提供连续账本事件片段及相邻 prefix hash、分项估值、锁定汇率和全部外部流；服务重新计算分项和本位币流，按 `(t0,t1]` 与事件序号确定区间。缺少流前估值时 TWR 不可用；已确认过期的价格或汇率可保留记录金额的差额，但不发布精确 TWR/XIRR。独立数值服务的结果不能作为已经贯通真实账本的历史收益。
- 限制：现有调用方尚不能从 ProjectStore 提供可信的连续历史 prefix hash/分项清单；契约内的声明只有与权威账本交叉核验后才可作为正式证据。

## D-030：黄金映射键在完整历史中唯一

- 状态：本地回归覆盖 A→B→A 重放
- 决定：个人完整估值应用黄金映射时，若新候选 mapping key 曾在历史中出现、但不是当前最近映射，则拒绝重新应用，并保持 generation、映射历史和库存不变。连续重放当前键仍按幂等返回。不能通过重命名 revision ID 绕过相同经济输入的唯一键约束。
- 原因：规格要求资产版本、金价和汇率组合幂等；重复应用旧键会错误追加一版映射并重排金豆。

## D-032：流水 CSV 导出是明文表格

- 状态：本地服务与页面测试通过；Android 系统文件选择器尚未验收
- 决定：个人已保存流水可显式选择新文件后导出 UTF-8 BOM CSV，按入账序号包含冲销原记录。金额与数量仍用原十进制字符串，扩展字段保留在原始事件 JSON 列；其他文本列避免电子表格公式执行。超过 10000 条或 16 MiB 时拒绝，不截断。页面明示 CSV 是含敏感数据的明文流水表格，不能代替完整 JSON 备份；服务拒绝已存在的目标并写后校验大小与 SHA-256。
- 限制：Godot 文件检查与重命名之间尚无法证明跨进程严格不覆盖，见 KI-012。Android 文件提供者的授权、保存位置和重名行为需真机测试；也未实现报告导出。

- 状态：荣耀 Magic 6 Pro / MagicOS 10（Android 16）的 v2 实机缺陷由用户报告；v3 修复候选已通过本地测试和 APK 静态检查，尚未在该机复测。
- 决定：普通 Android App 显式请求竖屏并用 `expand` 适配长屏；提高主界面文字、输入和按钮尺寸。金豆仍采用真实刚体、9.81 m/s²、60 Hz 与 1.0 时间倍率；碰撞壳用 16 个更厚、重叠的墙面及封闭顶底，金豆凸碰撞体由 74 点降为 26 点，保留 CCD。启用全局物理插值，使渲染帧间的刚体位置过渡更平滑；按 `_process` 更新的生态节点单独禁用插值，以免其逐帧动画被旧物理姿态拉回。维护 50 豆强摇晃/倾斜/倒置和 300 豆布局边界回归，并在导出后检查 Android manifest 的方向值。
- 依据与限制：修复前新回归实际越界，修复后边界通过；`inspect_personal_layout.gd` 的生态页碰撞布局首次失败，调整镜头后通过；440×960 桌面截图可见页脚完整，v3 manifest 有 `screenOrientation=1`。桌面 headless 帧时间不代表手机帧率；需在同一荣耀手机确认竖屏满幅、快摇防穿透与肉眼流畅度，再按规格采集 300 豆持续 60 秒实际帧时间。动态壁纸仍是独立未实现路径。
