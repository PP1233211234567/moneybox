# 金豆罐个人资产总账实施方案

版本 v1.1　日期 2026年9月27日　用途 产品调整与 AI 开发交接

本项目首先在手机上提供完整的个人资产总账，把账本中的总资产折算为黄金等值克数，再以透明玻璃罐中的金豆呈现。金豆按正常时间尺度和接近现实的重力、惯性、碰撞表现滚动、弹起与下落，不采用刻意缓慢的漂浮式运动；用户可以自愿合成不同重量的金豆。罐子还可切换为包含海草、鱼虾和环境变化的生态皮肤，形成长期陪伴的小型观赏系统。安卓版本以动态壁纸为核心展示方式，iOS 按其公开能力提供 App 内互动、小组件和壁纸导出。

本方案把原有总账功能与新增展示体验整合为一份实施依据。产品所有者可以修改参数和规则；实施 AI 必须把需求落实到代码、界面和验收证据。文档能减少交接歧义，但不能代替真机验证、视觉确认或上架审核。任何尚未实现或尚未验证的内容，都不得被标记为已完成。

## 01 使用方式与需求效力

### 阅读与修改

产品所有者先阅读第02至第08章，确认体验与业务规则；开发者随后落实第09至第17章。第18章提供逐项验收，第19章提供可直接复制给 AI 的开工指令。每次修改保留原需求编号，并在第20章登记变化。

Word 用于批注与修改；Markdown 用于版本管理和 AI 读取。两份内容在本版交付时一致。进入开发后，以仓库内 docs/IMPLEMENTATION_SPEC.md 为唯一生效副本。Word 的修改应先同步到该文件并增加版本号，避免两份同时成为不同的指令来源。

### 三类规定

- 已确认需求：本轮用户明确提出的功能，或从原总账方案继承的既有功能范围。不得因为实现方便而删改。
- 建议默认值：本方案为使开发可以开始而提出的具体选择。可由产品所有者修改；未修改时按该值实施。
- 平台边界：操作系统、设备或商店能力带来的约束。无法通过改变文案消除，需要验证、降级或另定平台方案。

最新的明确用户修改优先于旧版文档。本方案在“手机优先、以金豆罐替换经营游戏表现”上覆盖旧版的 Windows 首发和文明经营顺序；原有总账业务能力继续保留。旧文件中写明的实现状态只代表旧文件描述，不能作为当前代码已存在或已经通过测试的证据。

### 范围层级

体验原型先验证系统壁纸、真实物理和生态场景的核心交互；安卓可用版接入真实本地账本、自动行情和受控的自然语言录入；完整移动总账版落实继承的财务能力。后端先承担行情、AI解析、授权和运维，不要求首版把完整账本上传云端。iOS 适配版提供平台可实现的形态；多设备云同步为后续扩展。分阶段只是交付顺序，不等于删除后续功能。发布说明必须列明本次覆盖的阶段。

## 02 产品目标与不可丢失的需求

产品的主要体验是：用户更新资产后，能在一个随身可见、安静、具有重量感的玻璃罐中看到自己的积累。账本是财务依据，金豆罐是账本的可视化投影。用户不需要每天完成游戏任务，也不需要为了获得金豆增加交易次数。

本章是产品所有者优先修改的位置。参数修改只影响注明的范围；会改变历史财务结果的选项必须建立新计算版本。不得通过调低参数掩盖尚未实现的核心功能。

## 04 原有资产总账的继承范围

### 建账和资产范围

保留三种建账方式：导入完整历史、从某日建立期初状态、只记录当前余额。最后一种不是删去完整总账，而是降低初次使用门槛。余额级数据不得编造成本、历史交易或投资收益。

支持同花顺、支付宝、汇丰香港、其他银行券商、现金、公积金等自定义来源。同花顺等展示渠道和实际托管账户要分开，避免同一持仓在两个来源重复计入。机构列表可扩展；账户选择后继承市场、币种、收费计划和成本法。

| 类型 | 最低录入内容 | 需要保留的能力 |
|---|---|---|
| 股票和ETF | 账户、证券身份、市场、币种、数量、价格、日期 | 买卖、批次成本、派息、费用、税款、公司行动 |
| 公募基金 | 基金及份额类别、份额或确认金额、净值、日期 | 申赎、分红、再投资、按持有期处理费用 |
| 现金 | 账户、币种、余额或变动、日期 | 存取、转账、利息、费用、调整 |
| 存款 | 本金、币种、起息日 | 利率、期限、到期、提前支取、利息 |
| 公积金和养老金 | 账户、日期、余额或缴存额 | 缴存、提取、利息、期初和余额调整 |
| 实物黄金 | 克数、估值价格、币种、日期 | 买卖、成本、费用及估值来源 |
| 其他估值资产 | 资产名、估值、币种、日期 | 估值依据、所有权和更新记录 |
| 房产车辆及负债 | 按旧路线保留扩展设计 | 后续启用后总资产与净资产分列 |

至少预置 CNY、USD、HKD、EUR、GBP、SGD。金额与行情保留原币；汇总使用明确的本位币汇率。人民币总资产继续可查看，即使用户选择另一展示币种。

### 流水与余额之间的关系

期初、买卖、股息、利息、费用、税款、外部存取款、内部转账、公司行动和更正均形成可审计事件。现金、持仓、成本和收益是事件投影，页面不能直接改计算结果。

仅记录总余额时，建立范围明确的余额账本。后续转为账户明细时，采用“替代期初”向导：显示原汇总余额、拟导入明细总额和差异；提交后原汇总来源退出当前估值，但历史保留。禁止把旧的总余额再加到拆分后的账户总额上。对单一账户也适用同样的余额级与明细级互斥规则。

总资产等于去重后资产市值之和；净资产等于总资产减负债。向金豆罐输出的默认是总资产，不能使用名为 net_worth 的字段偷偷替代。若用户切换到净资产，页面和壁纸全部改用“净资产”标签，记录一次映射设置变更。

### 投资估值和收益

持仓市值为数量乘参考价格，再按锁定于该次估值的汇率折算。所有价格都带币种、行情时间、来源、延迟状态；历史成交价不能覆盖时间更新的行情。批量刷新结束后统一生成一次估值结果。某个接口失败时保留旧值并标出过期，不能把价格改为零。

保留 FIFO 与移动平均成本法，默认 FIFO。账单实际成交、费用和税款优先于估算；成本法变更创建新计算版本。ETF 管理费若已在净值中体现，不再虚构一笔现金费用重复扣除。

保留已实现收益、未实现收益、派息、利息、费用和净投入；区分原币投资表现与本位币估值变化。仅有当前余额或期初缺成本时，相关收益显示“不足以计算”，不能填零冒充已知结果。

完整移动总账版提供 TWR 和 XIRR。TWR 需要外部现金流边界上的有效估值；缺失时标为近似或不可计算。XIRR 固定日数规则，检测无解与多解；不能强行返回看似合理的年化数值。收益算法可以使用专用数值求解器，金额、现金流、成本和权威存储仍使用十进制定点或高精度十进制。

### 曲线与区间测量

保留全部、日K、月K、年K视图及两点区间测量。这里的K线来自用户资产快照，只反映已记录的高低点。缺失日期显示断点或带标识的持平线，不生成虚构波动。

区间净投入必须使用起始快照之后、结束快照之前或同时发生的外部资金流，即统一采用区间 (t0,t1]。同一时刻用事件顺序号处理边界，防止把起初已含的资金流再次扣除。

区间资产变化额＝期末值－期初值；扣除净投入后的资产变化＝期末值－期初值－区间外部净投入。资产增长率的分母为零或负数时，不给误导性百分比。没有覆盖全部账本的完整现金流时，不宣称该差额是严格投资收益率。

### 派息费用税务导入和对账

派息保留预计、建议、待到账、已确认状态；提醒不增加现金。确认后写税前金额、预扣税及净到账。红利再投记录关联的股息与买入，不能记成外部新增储蓄。

收费中心保留汇丰香港、Firstrade、uSMART、IBKR、老虎、富途、长桥、支付宝基金等机构的适配入口。规则按计划、渠道、市场、产品、交易方向和生效日期匹配；实际账单可覆盖并保留差异。不得凭旧说明文件硬编码当前收费数值。

税务模块保留年度、税务居民配置、来源国地区、所得类别、取得成本、境外已缴税、锁定汇率、凭证和规则版本，输出情景估算与资料底稿。税率、抵免和申报日历由另行核验的规则包提供，本方案不规定当前法定税额；缺少有效规则时仍可整理底稿，不输出假精确税额。

导入流程为选择账户、字段映射、证券匹配、预览、查错、去重、原子提交、对账。保留粘贴表格和 CSV；原始文件可删除，保留必要哈希与映射记录。批次作废通过冲销或作废记录实现。最终资料支持 CSV、完整 JSON 和报告导出。

对账依次比较账户总额、各币种现金与持仓、流水费用和待交收项目。手填券商总额只形成检查点，不能无痕覆盖持仓或把差额认作收益。

### 自然语言交易录入

用户可以输入“今天在汇丰香港用3001美元买了5股VOO，其中手续费1美元”一类自然语言。客户端先用本地规则识别日期、账户、证券、方向、数量、金额、币种和费用；仍有歧义时，只把当前输入和最少必要的本地候选ID发送给后端AI解析。不得上传完整账本、资产总额、账户号码或无关历史。

AI输出必须符合版本化的 TradeDraft JSON Schema，并返回原文片段、字段值、置信度、缺失项和假设。它只能建立待确认草稿，不能创建正式流水、计算持仓、推测成交价、补造费用或直接更新总资产。确定性的校验器核对账户、证券身份、币种、金额等式、日期和重复交易；缺失关键字段时向用户追问，存在异常时显示原因。

确认页逐项展示交易方向、账户、证券、数量、单价或总额、费用、税款、币种、成交与结算日期，以及确认后的现金和持仓变化。只有用户明确确认后，LedgerCore才以命令提交；提交成功后再重算持仓与总资产。关闭AI、服务不可用或额度耗尽时，普通表单、粘贴表格和CSV仍完整可用。

## 05 手机页面与导航

建议采用四个一级入口：金豆罐、总览、账本、我的。原来八个桌面入口被重新编排到手机菜单中，功能保留。核心编辑页面使用底部固定操作区，金额键盘支持小数和对应币种。

## 06 总资产与黄金映射规则

### 资产版本和映射版本分开

总账继续按照原规则生成估值快照。金豆罐只消费已经提交且符合用户映射策略的估值版本，生成独立GoldMappingRevision。默认策略允许完整自动行情批次每日最多建立一次映射；交易确认后也可立即建立。单纯打开页面、旋转手机、购买皮肤或重复读取同一版本不能再次增加或减少金豆。

“更新资产”按钮整合两个步骤：保存账本或刷新估值，然后预览本次黄金折算并应用。自动行情批次也可以建立新的估值快照；默认每日最多自动应用一次完整估值到金豆映射，用户可改为每次确认或仅手动。保存财务数据不依赖金价接口成功；金价暂不可用时账本正常保存，罐子保留上一次有效映射并标明更新时间，禁止把新金额与旧克数伪装成同一次快照。

建议允许单独“按当前金价重新折算”。这是用户主动建立新映射，资产快照可以不变。按钮需要显示由于资产行情和黄金价格分别造成的增减；普通刷新相同数据不建立重复映射。后台因系统限制未按计划运行时，在下次打开App补抓最新行情，但不伪造后台执行时间，也不循环补建多个历史映射。

### 公式和单位

设 A 为本次绑定指标的本位币金额，P 为同币种每克黄金参考价格，G 为黄金等值克数。A大于等于零且P大于零时：G＝A÷P。

如果数据源返回美元每金衡盎司报价 Q，美元兑本位币汇率为 F，则 P＝Q×F÷31.1034768。盎司必须明确为金衡盎司，不能使用常衡盎司。数据源本来返回每克报价时不得再除一次。首版建议采用来源明确的现货中间参考价；它不包含金饰加工费和实际买卖点差，不等于可成交报价。

把资产和报价保留为原始十进制字符串，G 的投影计算保留至少12位小数，使用明确的舍入规则。显示两位或四位小数不能反写权威结果。基础金豆数量为 floor(G)，余量为 G－floor(G)。计算出整克边界时以未格式化的投影值判定。

资产负值只会在允许负净资产等模式出现。此时保留真实负数，罐为空，显示“当前净资产为负”；不创建负金豆，也不丢弃负值。首次缺少金价时可使用用户明确输入的参考价，必须标为手工；不能静默使用虚构价格。

### 完整重算与原因拆分

每次应用映射重新计算全部 A÷P，不能只把增量资产按当日金价累加到旧金豆上。这样始终保持“当前资产等值黄金”的含义。

如果希望解释变化，可固定采用先资产后金价的展示分解：资产变化项＝(A新－A旧)÷P旧；金价变化项＝A新÷P新－A新÷P旧；两项之和等于G新－G旧。这只是说明映射变化的分解，不是投资收益分解；新旧币种或指标不一致时不比较，显示“计量口径已更改”。

| 示例 | 输入 | 预期结果 |
|---|---|---|
| 首次建账 | A为100000，P为1000 | G为100克，100颗1克金豆 |
| 增加资产 | A改为103750，P仍为1000 | G为103.75克，增加3颗，余量0.75克 |
| 金价上涨 | A仍为100000，P改为1250 | G为80克，减少20克，金额不变 |
| 相同数据刷新 | 资产和选用报价标识都未变 | 不重复投放，不建立重复展示变更 |
| 非整克 | A为23700，P为1000 | 23颗和0.7克进度，不能显示24颗 |

本章数值均为测试示例，不代表当前市场价格。

### 行情质量和失败处理

每次报价必须保存来源、报价时间、取回时间、报价币种、单位、延迟或手工标识、所用汇率。最新取回时间不能代替报价本身的时间。缓存过期阈值为建议配置，初始设为24小时；休市时显示最近有效报价，不伪装成实时。

有效的新报价可直接用于自动估值或更新预览。只有过期缓存时，用户可明确选择“按该历史参考价折算”；没有任何有效价格时，提供手工录入或稍后折算。拒绝零、负数、非数值、单位不明和异常格式；异常幅度只触发复核提示，不擅自修改价格。

批量刷新使用更新批次，记录各资产实际报价时间，不能宣称所有持仓在同一秒估值。金价和汇率的混用时间应可展开查看。后端获取行情时只需要证券市场代码和币种，不需要用户资产金额或账户内容。报价批次失败、许可到期或供应商限流时，客户端继续使用最后有效版本并明确显示状态。

## 07 金豆数量合成和容量

### 权威重量与物理对象

财务层输出准确的G；表现层保存各金豆的面额、身份和所属罐子。必须满足：所有1克金豆数量＋10×所有10克金豆数量＋小数余量＝G。物理引擎的位置、速度和碰撞结果不能参与金额计算。

每颗基础金豆代表1克。10克金豆的物理质量为基础金豆的10倍，同形同密度下线性尺寸约为基础豆的2.154倍。不能为了在视觉上挤下更多金豆，把10克豆画得与1克豆完全相同且没有面额区分。皮肤允许适度造型变化，但计量含义保持一致。

### 自愿合成与拆分

在整理页面进入选择模式，用户选择十颗1克豆或使用“选取十颗”；预览“10颗1克合成1颗10克”。确认后创建 JarOperation，原十颗进入已合成状态，生成一颗具有新ID的10克豆。动画只演示已提交的结果；中途关闭页面不会重复执行或丢失重量。

拆分操作反向执行。数量不足时禁用合成并说明还差几颗。不用长按系统桌面或锁屏手势触发合成。可以提供“连续合成若干组”，但必须先显示组数和总重量，由用户主动确认。

### 资产减少后的处理

先更新小数余量，再按目标整克数调节整数金豆。默认优先移除最近加入的1克豆；若数量不足而剩余有10克豆，因重估需要将其中一颗拆为十颗，再移除所需数量。例：只有一颗10克，目标变为9克，应得到九颗1克。

上述拆分是维持准确重量所需的重估调整，不是自动合成奖励；在更新预览中说明“为匹配最新等值，将拆开一颗大金豆”。保留其操作来源。下降动画采用平静淡出或移出，不碎罐、不惩罚。更正错误数据与市场重估分别记录原因。

### 满罐与大量资产

不得为了性能自动把1克规则改为“一颗代表100克”，不得强迫付费扩容或合成。建议将储藏空间分成多个相同玻璃罐，罐数不限于付费权益。首页和壁纸展示用户选定的一罐，页面同时显示全部黄金等值；罐编号可按用户偏好隐藏。

每罐设定可配置的容积上限，并设独立物体数上限，建议起始值300个。任何一项将超限时，新金豆转入下一罐，两个上限都在性能测试后锁定。容量按经碰撞测试可稳定容纳的体积定义，不单靠理想球体堆积率决定。一个10克物体不能按一个1克物体占用体积。

所有未展示罐只保存状态，不持续计算物理；当前罐完整显示自身金豆，所有罐合计满足G。打开某罐时恢复其姿态或生成不重叠的稳定布局，不播放历史入账。用户拒绝合成也能正常使用。

不同设备可恢复相同金豆面额和归属，但物理布局允许略有差异。跨设备要求财务结果一致，不承诺浮点物理模拟逐帧完全一致。

## 08 视觉与物理交互

### 基础美术规格

首套皮肤采用柔和的半写实三维风格。玻璃应清透、有厚度、边缘高光和轻微折射，能够看见内部金豆；金豆为圆润金属，颜色有明暗变化，避免整片刺眼黄色。背景保持安静，以暖白、米灰和柔和阴影为主。治愈感来自色彩、光照、构图和声音，不通过整体降低物理速度制造。以下颜色是初始建议，不是已经确认的最终美术。

| 项目 | 建议值 | 验收关注 |
|---|---|---|
| 背景 | #FAF7F0 | 不影响系统文字和图标辨识 |
| 背景阴影 | #D9D1C3 | 接触阴影柔和，罐子有落地感 |
| 金豆主色 | #D9A441 | 材质高光和粗糙度共同呈现金属 |
| 金豆亮部 | #F4D986 | 高光面积克制，无持续闪烁 |
| 正文 | #34312C | 正常字号与浅色背景有足够对比 |
| 玻璃 | 中性透明材质 | 不使用白色实心瓶伪装透明 |
| 构图 | 竖屏全幅，罐体宽约屏幕65%至80% | 位置可调，避免被时钟通知遮住主体 |

制作三个用于人工确认的视觉样张：空罐、约三分之一罐、接近满罐；再提供1克与10克同屏对比。静态概念图只能作为美术参考，最终必须有可拆分的罐模型、金豆模型、纹理和光照配置。AI生成的图片不能直接当作可碰撞三维模型。

玻璃瓶体默认有瓶盖或封闭边界，避免手机倒置后金豆逃出。新增金豆时可短暂表现瓶盖开启或从上方落入；物理注入路径需要单独控制，结束后恢复封闭边界。产品所有者如改为开口瓶，应明确倒置时如何保留资产表现。

### 真实时间尺度和碰撞

基础金豆罐按干燥玻璃罐建模。物理引擎时间倍率固定为1.0，重力基准为9.81米每二次方秒；场景先定义明确的现实尺寸，再统一换算为引擎尺度。不得给全部金豆施加与现实不符的高阻尼、缓慢插值、漂浮曲线或减速时间轴。安全限幅只能处理传感器尖峰和穿透风险，不能让正常下落变成慢动作。

建议基础罐内部高度约0.24米，1克金豆等效直径和不规则外形按视觉样张确定。无初速度自由下落测试可选0.10米和0.20米高度；忽略空气阻力时理论时间分别约0.143秒和0.202秒。实机录屏允许因碰撞体形状、接触和帧采样产生约20%的偏差，但不得稳定慢到理论时间的两倍以上。落地后应有清楚的第一次撞击、短促反弹或翻滚、连续衰减和最终静止，不能像棉花、磁吸物或水中悬浮物。

1克和10克金豆使用同一重力加速度；质量影响碰撞冲量和相互作用，不改变真空式下落加速度。线性阻尼和角阻尼从低值开始调节，摩擦、恢复系数和质心根据实机视频校准。为防高速穿透，可以使用连续碰撞检测、子步进和合理的碰撞边界厚度，不得用全局减速代替稳定性处理。

### 三维模拟与坐标

建议使用真正的三维刚体模拟和固定观察相机。手机竖直时金豆主要向画面底部堆积，手机平放时沿屏幕深度方向靠向后壁，倒置时靠向瓶盖。不能只做左右滚动，却宣传与现实手机姿态完整一致。

传感器坐标必须变换到当前渲染和屏幕方向。重力向量和线性加速度分别读取；若只用加速度计，则先估计重力，避免把重力重复计算。作用力由手机姿态、线性加速度和适度滤波共同产生；旋转带来的高级惯性项可在后续拟真档增加，不能用“陀螺仪”三个字代替算法说明。[R01]

物理世界使用统一的米、千克、秒单位，并按需要做一致的内部尺度换算，不能单独放大半径却保留不匹配的力。显示长度可以整体缩放；相机和模型共享同一缩放体系，质量比例保持1比10。玻璃内壁用静态复合碰撞体，金豆用凸碰撞体，避免将透明渲染网格直接当作动态凹形碰撞体。

| 情境 | 应有表现 | 禁止的表现 |
|---|---|---|
| 缓慢左倾 | 金豆立即受新的重力分量影响，沿低处滚动并重新堆积 | 延迟数秒后才柔和漂移，或仅整张图平移 |
| 快速摇晃 | 相对惯性产生有力度的弹起、旋转和碰撞 | 播放固定循环视频，或用慢动作削弱撞击 |
| 倒置手机 | 金豆落向封闭瓶口并相互碰撞 | 金豆穿过瓶盖消失或减少账面克数 |
| 平放手机 | 金豆向背面移动，仍在瓶体内 | 所有金豆突然悬空 |
| 长时间静置 | 金豆逐渐停止，进入休眠 | 无输入时持续抖动发热 |
| 增加资产 | 只投入新增的整数克部分 | 每次打开都重新投放全部存量 |
| 切换皮肤 | 克数与面额保留，必要时重排位置 | 更换皮肤导致资产清空 |

### 动画与反馈

首次初始化建议在2秒内完成视觉建立；少量新增采用逐颗从真实入口高度释放，进入物理世界后不再沿预设曲线缓慢飘落。默认最多展示20颗逐颗动画，其余直接并入稳定布局并显示本次增加克数。此限制只影响演示时长，不改变物体和克数总额。资产为零时呈现空罐，不加装饰金豆冒充资产。

合成动画约0.6至1.2秒：选中豆聚拢、形成大豆、自然落回。常规交互可开启金属与玻璃碰撞音效；使用碰撞冲量阈值、同时播放上限和短时间冷却，防止密集碰撞产生爆音。壁纸默认静音，也不在口袋里播放声音。

### 生态罐皮肤

生态皮肤的默认结构为双层玻璃罐：内层密封干燥舱存放金豆，保持本章规定的正常重力、快速下落和玻璃碰撞；外层透明水域生长海草并饲养小鱼和虾。两层在视觉上形成一个完整小生态系统，但碰撞世界彼此隔离。鱼虾不能推动、吞食或遮蔽权威金豆，金豆也不能撞死生物。若未来增加“整罐水下”皮肤，必须真实加入流体阻力和浮力并单独标注，不得把其慢速表现替代基础物理。

首个生态包建议包含两至三种海草、一种小型鱼和一种观赏虾。鱼具有巡游、转向避障、短暂停留、成群或独游等状态；虾可沿玻璃、底砂和植物表面缓慢活动；海草有轻微摆动和分阶段生长。水面、气泡和焦散光采用低成本着色或粒子表现，不要求实时流体模拟。生物使用自己的动画和行为层，不与财务刚体共用质量或碰撞规则。

生态系统是低压力陪伴功能。用户可以投喂、布置植物和查看成长，但默认不设置因数日未打开而死亡、资产受损或金豆减少的惩罚。离线时间只推进可解释的成长、昼夜和行为阶段；再次显示时直接恢复到合理状态，不补播整段离线游动。生物数量、稀有度和繁殖不按资产金额增长，也不作为投资收益奖励。

生态皮肤保存物种、个体ID、成长阶段、植物布局、上次更新时间和用户装饰。更换普通皮肤不会删除生态状态；卸载皮肤资源只移除可重新下载的美术包，不删除用户的生态记录。免费基础罐始终可用；付费生态包可以出售外观和物种组合，但不得锁住导出、账本、真实物理或金豆容量。

### 物理与性能建议初值

物理固定步长建议1/60秒，渲染与物理分离；慢帧限制每次追赶步数，避免恢复时一次补算长时间。恢复可见后将时间累计器清零，重新读取姿态，禁止把熄屏期间的时间差当作一次巨大物理步长。

建议物理参数起点：重力9.81米每二次方秒、时间倍率1.0、摩擦系数0.4、恢复系数0.25至0.45、传感器低通时间常数约0.05至0.1秒，强摇晃输入限幅为可配置值。它们是待真机调节的工程参数，不是实测黄金材料常数。大幅运动时启用连续碰撞检测或可靠子步处理，保证不穿透。任何参数调整都要同时复测下落时间、第一次碰撞、静止时间和耗电。

默认活动渲染30帧每秒，流畅档可设60帧；物理仍按固定步长运行，不能用降低渲染帧率改变下落速度。完全静置后停止连续绘制，仅保留必要的姿态监听或低频检查。不可见时停止金豆物理、生态动画、渲染、音效并注销不必要的传感器监听。低电量和发热时可降低生态个体更新频率、分辨率、阴影与帧率，但不能改变账面克数、物理时间倍率或强制合成。[R02]

## 09 平台实现与能力降级

### 安卓完整体验

使用 Android WallpaperService 承载系统动态壁纸，用户通过系统壁纸选择器启用。主屏幕和锁屏是否可分别选择，取决于设备和系统；不能用悬浮窗、无障碍服务或自制锁屏替换系统安全界面来绕过限制。[R02][R03]

建议首版最低支持 Android 10，最终 target SDK 和商店要求在构建阶段核验并锁定。版本号不作为本方案对未来商店政策的保证。首批测试至少覆盖用户自己的设备、一台接近原生系统的手机和一台不同厂商的手机。

壁纸实例可能同时包含系统预览、主屏幕和锁屏实例。每个实例可以有自己的短暂物理位置，但共享同一权威映射与金豆面额。预览不得改变正式金豆库存。多个实例同时出现时限制渲染资源，不允许每个实例各自消费一次新增资产事件。

系统进程被回收、手机重启、壁纸切换、屏幕旋转和 Surface 重建，都必须能从最后提交状态恢复。壁纸可见时读取已提交版本，数据库正在保存时继续展示旧版本，禁止读到金额新、克数旧的半更新结果。

重启后尚未首次解锁时，默认不读取受凭据保护的财务数据。显示不带金额的通用背景，首次解锁后恢复。若厂商自动恢复策略不同，兼容性报告必须记录；不把真实资产复制到不受同等级保护的存储中只为绕过该限制。

亮屏锁屏与熄屏常亮显示分别处理。本项目要求前者支持设备上可运动；AOD 不承诺持续三维运动。桌面启动器的图标位置、左右翻页和壁纸缩放须实测适配。用户可调罐体位置、大小和金额位置，不自动修改桌面图标。

### iOS 适配体验

iOS 提供完整账本和 App 内物理金豆罐；桌面与锁屏小组件呈现资产摘要或罐子快照。小组件不运行持续的传感器驱动物理循环，其更新由系统机制约束。不得将 App 内运行视频标成真实 iPhone 桌面效果。[R04]

用户可导出静态壁纸或兼容的 Live Photo，并手动设为壁纸。导出的金额和金豆数量是导出时的快照，后续账本变化不会自动改写该文件。Live Photo 的唤醒播放不等于持续响应手机运动；不得以此宣称实现安卓同等能力。[R05]

Live Activities 不作为永久运行的金豆罐。iOS 完整版本建立自己的能力表和验收范围；核心财务契约保持一致。正式支持的最低系统版本在 iOS 阶段决定，不能未经验证照抄安卓的生命周期策略。

## 10 推荐技术架构

### 技术选择原则

手机优先改变的是运行环境和展示承载方式，不改变第04章的财务功能。原方案中的 Godot 与 C# 可以作为已有代码的候选资产，但未看到实际仓库前，不能假定存在可复用的核心，也不能照抄旧方案中的软件版本号。

若从零开始，建议采用原生安卓外壳，避免把动态壁纸做成嵌套网页。UI使用 Kotlin 与 Jetpack Compose；业务核心使用纯 Kotlin/JVM 和 BigDecimal；本地数据使用 Room与SQLite；物理采用 Bullet 等成熟三维刚体库；渲染通过独立的 OpenGL ES 渲染层连接 WallpaperService 与 App 内视图。具体依赖版本在M0验证后固定。[R06][R07][R08]

若存在已验证的 C# 财务核心，M0先运行其既有测试并评估复用，不得无记录重写。必要迁移采用相同输入输出样例逐项对照。Godot Android库具备嵌入能力，但“可以嵌入App”不等于“已经适配动态壁纸Surface和多实例”；以M0实机原型决定是否保留该表现技术。[R09]

业务更新顺序为用户命令进入总账、建立估值、确认映射、更新金豆库存、通知展示。表现模块只得到必要的汇总金额、克数、时间和库存，不得到券商账户名、证券明细或税务凭证。这里的汇总值仍是敏感数据，不能称为匿名数据。

建议核心与壁纸在同一应用包中运行，由单一数据写入协调器串行提交。壁纸只读取发布后的展示状态。未来需要独立进程时，通过版本化IPC或只读发布快照传递，不让多个进程各自修改JarInventory。生态场景读取同一展示版本，但只写自己的场景状态。

### 客户端与后端边界

本项目采用本地优先的混合架构。手机端保存并计算权威账本，断网时仍能录入、查询、备份和运行金豆罐。后端首版负责行情密钥保护与缓存、自然语言解析、购买验证、服务配置和匿名运行指标；不要求注册，也不要求上传完整资产总额。启用多设备同步后，服务器才保存版本化用户事件，客户端仍保留完整离线副本。

客户端不得直接连接生产数据库，也不得把服务商密钥写入安装包。所有网络能力通过BackendApi调用，接口使用HTTPS、明确超时、请求ID和幂等键。服务端返回的行情、AI草稿和权益都是输入数据，必须经过客户端契约验证；远程响应不能直接覆盖本地账本。

后端首版采用模块化单体，而不是过早拆分微服务。一个可部署服务内部划分quotes、ai-draft、entitlements、sync、admin和observability模块，模块通过接口交互。用户量、故障隔离或独立扩容出现明确需要时，才把模块提取为独立服务。这样可以保持初期部署简单，同时避免未来功能都堆进一个无法替换的控制器。

建议服务端采用PostgreSQL保存关系和事件数据；缓存和任务队列首版可由数据库任务表实现，规模增长后再增加Redis等组件；对象存储只保存加密备份、许可文件或用户明确上传的附件。业务逻辑不能依赖某一家托管平台的私有表结构，数据库迁移脚本、OpenAPI和JSON Schema必须保存在仓库中。

### 自动行情服务与网络成本

应用提供 IStockQuoteProvider、IFundQuoteProvider、IFxProvider、IGoldPriceProvider、IFeePolicyProvider 接口。首先接入测试提供方和手工来源，安卓可用版必须接入至少一个合法可商用的证券行情来源、一个汇率来源和一个黄金参考价格来源；不支持的市场明确回退手工价格，不能将模拟接口写成线上行情完成。

QuoteGateway维护内部InstrumentIdentity与各供应商代码的映射，例如代码、交易所、币种、资产类别和份额类别共同确定证券，不能只靠ticker。公共行情由后端统一抓取和缓存，同一证券在一个刷新窗口内只向供应商请求一次。客户端只发送所需市场代码集合，不发送数量、成本或资产金额。报价必须返回source、quoted_at、fetched_at、currency、unit、delay、session和provider_symbol。

默认在打开App时请求最新可用批次；系统允许时每日执行一次后台刷新。服务器定时预热常用证券、汇率和黄金价格，客户端根据ETag或版本号避免重复下载。正式服务设置用户和IP限流、缓存过期、熔断、重试退避、配额告警和提供方健康状态。无网络时只影响新行情，不影响本地记账、查看、物理运行和备份。

行情许可属于上架前阻断条件。原型可以使用开发者计划或演示数据，公开App必须核对目标市场、实时或延迟属性、展示、缓存和再分发许可。服务商停用或价格不可承受时，通过适配器切换供应商；迁移只改变来源映射，不改账本事件和历史估值。[R15]

### 自然语言解析服务

客户端先执行本地轻量解析；需要AI时，对账户名、机构名和证券候选建立临时别名，只发送当前一句输入、语言、时区和允许的字段Schema。服务端不把API密钥下发客户端，不在普通日志记录原文；默认只保存请求ID、模型、Schema版本、耗时、token数、结果状态和非敏感错误码。若为排错保留原文，必须由用户主动同意、设定短期保留并支持删除。

ILanguageModelProvider封装不同AI供应商。请求要求结构化JSON或严格工具调用；服务端再次用TradeDraft Schema校验类型、必填字段、十进制字符串和枚举。合法JSON仍可能语义错误，因此草稿必须由确定性规则验证并由用户确认。模型不可查询或修改生产数据库，不可自行调用LedgerCore，也不负责计算总资产、成本、收益、税款、汇率或金豆克数。[R14]

自然语言功能设置单次输入长度、每日免费额度、用户限流、最大重试次数和费用熔断。优先使用本地规则命中常见句式，只有歧义或复杂输入才调用AI；模型或供应商切换不能改变TradeDraft契约。停服、超时、内容无法解析或额度不足时，原文保留在本地草稿箱并提供普通表单入口。

### API契约和兼容策略

BackendApi以OpenAPI描述路径、认证、错误码、分页和速率限制；交易草稿、报价批次、同步事件和展示事件另存JSON Schema。公开客户端只依赖数据传输对象，不依赖PostgreSQL表名。接口路径或请求头携带主版本，服务端至少兼容当前正式客户端和上一个仍在支持期的主版本；淘汰旧版本前先发布客户端升级提示和停止支持日期。

所有会产生状态的请求包含idempotency_key；重复提交返回同一结果。新增字段默认可选并给出安全默认值；重命名采用新增、双写、迁移、停读旧字段、最终删除的过程。服务器错误使用稳定机器码和可本地化说明，不能让客户端依靠英文错误文本判断逻辑。

### 数据库演进和灾难恢复

本地Room与服务端PostgreSQL分别维护迁移序列，迁移文件一经随正式版本发布不得原地修改。正式构建禁止启用缺失迁移时清空并重建数据库的选项。每次发布保存完整Schema历史，并用各已支持旧版样本执行逐版本升级、跨版本升级、迁移中断、空间不足、重复启动和恢复测试。[R12]

破坏性变更使用扩展、回填、切换、收缩流程：先增加新表或可空字段，部署兼容新旧结构的程序，后台分批回填并校验，再停止旧字段写入；确认旧客户端退出支持期后才删除旧结构。金额、数量、币种精度、事件ID和关联关系在迁移前后逐项对账，不能只比较行数。

生产数据库只通过版本化迁移任务变更，不执行无记录的临时SQL。迁移前在脱敏副本演练并创建可恢复备份；可事务化的DDL在事务中执行，大表变更采用低锁方案。备份至少包含定期完整备份与连续日志或等效按时间点恢复能力，另存恢复步骤和密钥职责。定期在隔离环境实际恢复并运行账本不变量检查，只有恢复演练通过才能声称具备灾难恢复能力。[R13]

云同步服务器不属于首个本地版本的运行前提。后端不可用时，用户仍拥有本地账本和完整导出。未来更换后端技术时，以OpenAPI、事件Schema、PostgreSQL迁移和导出格式为边界逐步替换，不要求推倒手机端、账本核心或用户数据库。

## 11 数据模型与精度契约

### 继承的数据实体

保留 Portfolio、Institution、Account、Instrument、LedgerEvent、PositionLeg、CashLeg、TaxLot、LotConsumption、Quote、FxRate、ValuationRun、Snapshot、FeeRuleSet、TaxProfile、TaxRuleVersion、TaxEvidence、ImportBatch、ImportMapping、ReconciliationCheckpoint、AuditLog与OutboxEvent。旧数据迁移逐表映射，并保留原ID、原币精度和原事件关联。

账户至少包含portfolio_id、institution_id、名称、类型、本位币、收费计划、成本法与归档时间。证券身份至少包含代码、市场和报价币种，不能只用代码唯一标识。账本事件至少包含事件类型、生效时间、结算信息、状态、外部编号、导入批次、更正引用和凭证索引。

建议使用稳定UUID主键；时间以UTC保存并记录业务时区。新库可选UUIDv7，旧库无需只为统一形式改写全部ID。金额、数量、费用、汇率和克数在JSON与SQLite中用规范十进制字符串保存，禁止经过二进制浮点转换后再回写。

### 新增数据实体

Bean记录可以在大规模情况下用确定性范围和操作日志压缩，但必须保留逻辑身份和合成关系。不能简单减少存储数量而损失克数。初始版本优先选择实现和审计都更清晰的逐颗记录。

服务端数据库至少区分auth、market_data、ai_draft、entitlements、sync和ops职责。market_data保存提供方、证券映射、报价及批次；ai_draft默认只保存脱敏后的请求元数据和结果状态；sync仅在用户开启同步后保存其版本化事件；ops保存迁移记录、任务状态和审计。客户端ID不能直接作为SQL权限边界，服务端鉴权后仍按用户和设备校验访问范围。

### 状态发布和并发

一条新映射和对应库存更新在同一数据库事务中提交，提交成功后发布展示版本。UI先展示待处理状态，不能先播放“增加成功”再尝试存库。显示金额、克数、豆库存和更新时间必须来自同一已提交版本。

AI草稿确认和账本提交是两个不同事务。确认命令携带草稿版本和幂等键；草稿在用户编辑后产生新版本，旧确认请求不得覆盖新内容。QuoteBatch先完整落库，再由ValuationService读取；生态状态保存失败不能回滚已经提交的财务事件或金豆映射。

相同资产版本、选用金价、所用汇率、指标和映射算法版本产生同一幂等键。合成和拆分使用命令ID另行去重；连续双击只成功一次。并发时采用expected_revision，发现已更新则重新预览，不覆盖对方操作。

动画不要求可靠重播：进程中断后可以直接恢复最终状态。数据提交必须可靠。消费方持久化最后已见版本，版本倒退或重复消息不应改变现状；事件顺序不确定时读取最新完整快照校正。

## 12 保存备份隐私与恢复

### 本地优先

未启用云同步时不要求注册。财务数据保存在应用私有目录，应用锁作为可选入口保护；没有实现数据库加密时，只能说明“本地保存”，不能宣传“全程加密”或“端到端加密”。皮肤、音效和本地物理不需要网络。

数据库启用外键、事务和编号迁移；迁移前做一致性备份。使用WAL时，不能仅复制主数据库文件而漏掉尚未合并的日志。采用SQLite一致性备份或经过验证的导出方式。迁移失败保留旧库，不继续启动半迁移数据库。

### 备份内容与恢复顺序

完整备份包括账本事件、账户资产、成本配置、报价汇率、规则版本、导入映射、对账、映射版本、金豆面额、生态个体与成长状态、皮肤设置以及用户选择的附件。未提交的TradeDraft是否纳入备份由用户设置决定；AI服务端请求日志不作为账本备份。SceneState属于可选缓存，丢失后可重新排列。

备份格式建议为版本化容器，包含manifest、Schema版本、内容哈希和加密参数。加密采用受维护库的认证加密，密码派生使用明确记录参数的成熟方案；不要自创加密算法或将解密密钥与备份明文放在一起。

恢复流程：选择文件、验证格式和哈希、核对兼容版本、预览账户及记录数量、保存当前库的安全副本、在临时库恢复并校验、原子切换、重新估值和恢复展示。错误密码、损坏文件或不支持的新版本必须保留现有数据。合并两个备份不属于第一版恢复行为，避免重复入账。

用户可随时导出完整JSON与CSV，不以付费或订阅到期阻止取回自己的数据。清空财务数据需要清楚展示影响范围并二次确认，成功后同步清除壁纸金额、映射缓存、小组件内容和敏感临时文件。已由用户导出到外部的文件无法由应用自动召回，应在删除说明中准确表述。

### 隐私与权限

日志不能记录账户名称与号码、证件、完整交易内容、资产金额、自然语言原文、API密钥或备份密码。默认诊断仅记录错误类型、应用版本、设备能力和匿名性能指标；如以后收集使用分析，应有单独选择，不能把真实资产作为埋点属性。

使用系统文件选择器导入导出；联网仅用于行情、购买、自然语言解析和用户主动开启的服务。首次使用云端AI前说明将发送的字段、处理方和关闭方式；默认不发送完整账本。通知权限只在用户启用提醒后请求。不申请通讯录、位置或无障碍权限来实现存钱罐。运动传感器权限和采样限制按实际系统版本核验，按最小所需申请。商店隐私申报必须覆盖应用和所有第三方服务处理的财务信息。[R16][R17]

应用锁与壁纸隐私是两个不同设置：锁住账本不自动意味着壁纸隐藏金额。设置页面必须明确说明，并提供联动选项。用户将展示改为隐藏时，先发布隐私状态再重绘，避免短暂闪现旧金额。导出壁纸和分享截图前显示内容预览及隐藏金额选项。

### 未来云同步

保留device_id、事件ID、版本和作废记录。云同步先定义加密、密钥恢复、设备撤销、删除、导出和冲突规则，再开发服务器。同步采用事件与版本水位，不以整库覆盖解决冲突；离线设备重连后按幂等键合并。财务事件同步不依赖模拟位置；生态状态可以使用较低优先级同步，冲突时不得反向修改账本。皮肤权益由平台购买记录管理，不能承诺一平台购买自动跨平台有效，除非另行实现账号权益体系。

## 13 完整状态与异常处理

| 状态或操作 | 用户看到的内容 | 系统处理 |
|---|---|---|
| 没有资产记录 | 空罐和建账入口 | 不生成真实金豆 |
| 金价首次不可用 | 账本已保存，等待折算 | 保留待应用操作，不使用零价 |
| 只有历史金价 | 显示报价日期及采用按钮 | 需明确采用后再生成映射 |
| 资产已改但罐未更新 | 罐显示上次完整版本，提示待更新 | 不混用新金额与旧豆 |
| 行情部分成功 | 展示成功及保留旧价的项目 | 一次批次估值，可追溯混合时间 |
| 后台行情未按时运行 | 显示最后成功时间，下次打开可刷新 | 不伪造后台刷新，不补建多份历史估值 |
| 行情许可或供应商失效 | 显示来源不可用和手工入口 | 熔断该提供方，保留旧价并允许切换适配器 |
| 自然语言信息完整 | 展示逐字段交易草稿和入账影响 | 用户确认后才生成账本命令 |
| 自然语言存在歧义 | 标出缺失或冲突字段 | 追问或转普通表单，不猜测成交事实 |
| AI超时或额度耗尽 | 保留本地原文和手工入口 | 不创建流水，不影响现有账本 |
| 合成正在提交 | 操作按钮暂不可重复点击 | 命令幂等，事务提交 |
| 合成动画被打断 | 再打开看到合成后的准确库存 | 不重复合成、不回滚已提交财务 |
| 资产下降 | 预览减少的克数及原因 | 调整库存，保留历史 |
| 超出罐容量 | 新增下一罐，可查看全部 | 不自动改面额、不付费解锁容量 |
| 壁纸被系统回收 | 再可见时恢复最后版本 | 重新创建Surface和物理状态 |
| 无运动传感器 | 提示运动感应不可用 | 触控观察或静态模式 |
| 锁屏不支持动态壁纸 | 提示设备限制和可用方式 | 不接管系统锁屏 |
| 设置为完全隐藏数值 | 无金额、克数和增减数字 | 所有展示实例同步 |
| 导入存在关键错误 | 显示行号与原因 | 不进行半批次正式入账 |
| 备份损坏或恢复中断 | 说明错误并保留原账本 | 临时库验证失败即丢弃 |
| 购买取消或待确认 | 权益保持原状态 | 不先解锁永久权益 |
| 购买后离线 | 已验证的本地权益继续有效 | 定期复核策略不阻断基本记账 |
| 更换皮肤失败 | 恢复基础皮肤 | 克数、库存与账本不变 |
| 生态资源尚未下载 | 显示基础罐或低资源预览 | 后台下载可恢复，不删除生态记录 |
| 生态模拟离线多日 | 直接显示合理成长后的状态 | 不补播离线动画，不造成生物死亡惩罚 |
| 数据库迁移失败 | 说明升级未完成并保留旧数据 | 停止打开新库，从安全副本恢复或等待修复 |
| 快速切换账户或页面 | 显示当前请求对应数据 | 丢弃过期异步响应 |

“刷新失败”“没有数据”和“真实数值为零”必须是不同状态。所有失败提示都给出下一步可执行动作，例如重试、手工输入或保留上次结果，不能只显示未知错误。

## 14 商业化与商店交付

### 权益建议

免费版保留完整基本数据访问、基础罐、1克与10克规则、真实重力体验、备份导出和核心壁纸能力。增强功能可采用一次性买断；生态皮肤、物种组合和装饰包可以单独售卖，但至少提供完整预览并确保基础罐不被削弱。云同步和超出免费额度的AI解析若具有持续服务成本，可另设订阅或用量包，但普通表单和本地账本不作为订阅权益。

具体价格留在上线配置中，不写入金融计算规则。建议先验证用户是否愿意为外观与体验付费，再决定买断价格。产品购买不能增加代表真实资产的金豆；不出售“虚构财富”混入账本。不做抽奖合成、奖励广告加豆或通过交易次数获得财富积分。

苹果与Google Play的数字功能付费按目标市场适用的商店规则实施，默认使用平台内购；地域例外在发行阶段核验。实现购买取消、待处理、成功、退款、权益撤销和恢复购买。旧的永久买断权益不因后续改订阅而被默默收回。[R10][R11]

### 上架材料

准备应用说明、真实设备截图、实际平台演示视频、隐私政策、数据安全表、支持邮箱、购买说明和测试账号或演示模式。iOS商店图不能伪装成正在运行的安卓动态壁纸，平台能力必须准确对应。

记录软件依赖、字体、模型、纹理和音效的许可证或制作来源。正式行情来源应允许预期的商业展示、缓存与分发；服务提供方尚未确定时，数据适配层可以完成，但线上行情不能验收为完成。

该产品记录与展示用户资产，不接受用户资金、不出售真实黄金、不托管资产、不自动交易。不要将“黄金等值”包装成实际黄金余额。若后续新增交易或托管能力，应另开产品与合规设计，不能沿用本方案直接启用。

正式提交前核对开发者身份、发行地区、收款资格、商店费用与当前审核要求。苹果对成熟壁纸类别要求有明显不同或改进的体验；本项目以可用账本和真实互动作为产品内容，不以装饰截图代替功能。[R10]

### 商业验证

先观察用户能否完成建账、启用壁纸、第二次更新资产，以及一到两周后是否仍保留壁纸。付费实验使用真实可购买的权益，记录试用到购买的转换；不把下载次数直接视为利润。

性能调查应包括用户是否因耗电、发热、隐私或画面遮挡关闭壁纸。默认使用自愿反馈和不含资产数据的诊断方式。未获得足够样本时只报告观察到的结果，不宣称已经验证市场需求。

以上是逻辑职责。Gradle模块数量可按实测维护成本合并，但财务、映射和物理之间的依赖边界必须保留。不能为遵循目录形式而建立大量没有实际作用的空模块。

### 每阶段完成标准

实现AI应报告修改了什么、为什么、如何验证，以及剩余限制。构建通过、测试通过、实机验证和商店发布是不同状态，必须分别记录。不存在真机或无法获得传感器数据时，可以完成本地工程工作，但对应验收标为未实测，不能编造录屏或通过结果。

任何本地或服务端数据库变更都要有迁移及恢复验证；金额与映射变更要更新金标准样例。已经正式发布的迁移文件不得重写，不能使用删库重建掩盖迁移缺失。纯文案或颜色微调不强制新增无意义单元测试，但仍需进行相应视觉检查。不得为了使测试通过而修改既定的金融结果。

测试数据、服务密钥与生产配置分离。真实账单、个人数据库和签名私钥不进入公开代码仓库。选择依赖后记录精确版本与许可证，避免依赖latest导致无法重现。

## 17 质量目标与实机测试方法

以下均为建议的工程验收目标，需在M0确定的参考设备上测量；不是对所有设备的性能保证。调低目标应登记原因和影响，不得只为掩盖回归而改指标。

| 指标 | 建议目标 | 测量条件 |
|---|---|---|
| 首次可交互 | 本地数据下冷启动3秒内 | 非首次安装，记录设备与数据规模 |
| 壁纸恢复 | 亮屏可见后1秒内出现完整场景 | 不包含系统自身解锁等待 |
| 物理流畅度 | 默认30FPS档，300个物体时95%帧在33.3毫秒内 | 固定画质、持续倾斜60秒 |
| 自由下落一致性 | 0.10米和0.20米测试高度的首次接触时间与理论值偏差不超过20% | 时间倍率1.0，无其他物体阻挡，使用高速录屏逐帧测量 |
| 碰撞质感 | 首次撞击清楚、衰减连续，无漂浮、磁吸或统一慢动作 | 1克与10克分别从固定高度释放并快速摇晃 |
| 静置稳定 | 10秒内明显静止，无持续肉眼抖动 | 水平稳定设备，静态环境 |
| 不可见活动 | 不持续渲染或推进物理，无音效 | 熄屏及被其他App完全覆盖 |
| 数据规模 | 10000条流水下常用列表首屏1秒内 | 重算任务异步且显示进度 |
| 行情刷新 | 命中缓存时3秒内返回批次；失败项目有明确旧值状态 | 固定20个证券、3个汇率和1个黄金标的 |
| AI草稿 | 正常网络下10秒内返回或进入可恢复失败状态 | 固定20条中英文测试语句，不允许无限重试 |
| 幂等 | 重复100次同一映射事件结果不变 | 比较库存及财务哈希 |
| 异常恢复 | 30次随机中断与重启无提交数据丢失 | 保存、导入和合成过程分别注入中断 |
| 备份恢复 | 完整逻辑数据一致 | 恢复到干净安装后逐项校验 |
| 生态性能 | 300颗金豆加建议上限生态个体仍达到选定性能档 | 双层生态罐、植物摆动、鱼虾行为同时开启 |

耗电使用同一手机、同一亮度、同一网络和温度条件，对照静态壁纸与动态罐。分别记录静置、持续晃动、日常亮灭屏三种情况，每轮至少30分钟，并重复测量。报告平均电流或系统能耗、温度变化和帧率；不预先承诺“每天仅耗电1%”。出现明显发热、持续后台活动或频繁崩溃时，应先修复再扩大测试。

美术验收由产品所有者根据三个基础样张和实机录屏确认：玻璃是否像透明实体、金豆是否有重量和速度感、第一次碰撞是否有力度、10克豆是否合理、背景是否安静、日常图标是否清晰。生态皮肤另确认双层结构是否看得懂、海草和鱼虾是否自然、是否遮挡金豆与金额、长时间观看是否杂乱。开发者不得用一句“采用治愈风格”代替这一步。

基本无障碍包括系统字体放大后表单可用、金额可被读屏准确读出、主要操作触控区域足够、减少动态效果模式可用。读屏不逐颗朗读数百颗金豆，提供汇总信息。开启减少动态效果时保留真实金额和操作结果，弱化非必要动画。
